# Platform — Calendar & Reminders

## Purpose
Give users one place to understand time-based commitments across Re:Solve without turning the product into a full calendar replacement.

## Sources
Calendar can aggregate:
- project milestones
- task due dates
- client actions
- approvals
- invoice due dates
- service renewals
- domain/SSL expiries
- maintenance windows
- meetings/booking records
- plugin events
- synced Google/Microsoft events where configured

## Views
- Agenda
- Day
- Week
- Month
- My Calendar
- Team Calendar where permitted
- Client/Project/Property filtered calendar

## Reminder model
Reminder fields: subject, related record, recipient, due time, recurrence, channel policy, snooze options, completion state and source.

Reminders can be manual or generated by domain rules. A reminder is not a substitute for the source record's due date.

## Actions
- create personal reminder
- snooze
- mark done
- open source record
- reschedule where permitted
- assign follow-up

## Integrations
Calendar connectors may sync selected events to Google/Microsoft. Re:Solve must track sync identity/state and avoid duplicate event creation. External calendars remain external truth for their native events; Re:Solve remains truth for Re:Solve records.

## Notifications
Reminder delivery can use in-app/push/email/WhatsApp according to user and system policy. Repeated reminders must deduplicate/escalate rather than spam.

## API / MCP
Examples: list_my_agenda, create_reminder, snooze_reminder, list_upcoming_deadlines. External calendar write operations require connector scopes.

## PWA/mobile
Agenda is the primary mobile view. Push notifications deep-link to source records. Time zones, locale and daylight-saving behavior must be explicit and tested.

## Lovable build slices
1. Agenda and unified time-source demo data.
2. Week/month views and filters.
3. Reminders/snooze/recurrence.
4. External calendar connector mapping.
5. Mobile/PWA push and timezone polish.
